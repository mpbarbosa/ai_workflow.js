### RI-001 — AI cache key contains raw filesystem path causing ENOENT errors

- **ID:** RI-001
- **Source step:** step_20, step_22, step_23
- **Type:** code-bug
- **Priority:** Medium
- **Path:** src/steps/step_20_async_perf_review.js, src/steps/step_22_accessibility_review.js, src/steps/step_23_perf_review.js
- **Description:** Cache keys are built as `` `step_XX:${projectRoot}:${count}` `` where `projectRoot` is an absolute path (e.g. `/home/user/project`); when `AiCache` appends `.txt` and uses `path.join`, the `/` characters in `projectRoot` create nested directory paths that do not exist, causing ENOENT errors and silently skipping AI analysis for these steps.
- **Fix:** In `src/lib/ai_cache.js`, add a private `_safeKey(key)` method that replaces path-unsafe characters (`/`, `:`, `\\`) with `_` before using the key as a filename in `has()`, `get()`, and `set()`; then update all three call sites.
- **Status:** done
